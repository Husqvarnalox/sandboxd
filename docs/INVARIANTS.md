# Invariants

Properties sandboxd must keep regardless of what a workload or a client does.
Each one names the code that enforces it and the test that checks it. "Unit"
tests run anywhere with `make test-race`; "Linux" tests run as root in the
privileged container started by `make test-integration`.

| # | Invariant | Enforced in | Checked by |
|---|-----------|-------------|------------|
| 1 | A job is in exactly one state and only follows the transition table: `queued → starting \| cancelled`, `starting → running \| failed \| cancelled`, `running → succeeded \| failed \| cancelled \| timed_out`. | `internal/job/state.go` (`transitions`, `CanTransition`), `job.Transition` / `job.Finish` | unit: `job.TestTransitionTable`, `TestJobLifecycle` |
| 2 | Terminal states are immutable. Once `Finish` succeeded, no later `Transition` or `Finish` changes state, exit code, reason or timestamps. | `internal/job/job.go` (`Finish` checks `Terminal()` before writing; `Transition` rejects terminal targets) | unit: `job.TestTerminalStatesAreImmutable`, `TestFinishRejectsNonTerminal`; executor `TestCancelExitRace` (cancel racing exit yields one state) |
| 3 | Every job that leaves `queued` reaches a terminal state, with a log buffer that is closed **after** the final transition. Covers start failure, runtime error, timeout, cancel, shutdown, slow pipes and a process that ignores SIGKILL. | `internal/executor/task.go` (`Run` ends in `finish`, `defer logs.Close`; `drainTimeout`, `killTimeout`), `Discard` for never-started jobs | unit: `executor.TestOutcomes`, `TestTimeout`, `TestCancelQueuedNeverStarts`, `TestCancelDuringStart`, `TestShutdown`, `TestLargeOutputIsBoundedAndDoesNotDeadlock`; api `TestLogsFollow` (state event is last) |
| 4 | At most `MaxConcurrent` jobs run at once; waiting jobs are served FIFO; a full queue rejects with `ErrQueueFull` (HTTP 429) instead of growing. | `internal/scheduler/scheduler.go` (`Submit`, worker loop) | unit: `scheduler.TestConcurrencyLimit`, `TestFIFOOrder`, `TestQueueFull`; executor/api `TestQueueFull`; Linux: `e2e` queue-full case |
| 5 | Cancelling a running job terminates **every** process it created, not just the main one: SIGTERM to the workload's process group, then after the grace period SIGKILL to the whole cgroup, and init's exit kills the PID namespace. | `internal/executor/task.go` (`terminate`), `internal/runtime/linux/process.go` (`Signal`, `Kill` → `cgroup.Kill`), `internal/runtime/linux/init.go` (`supervise`, final `kill(-1, SIGKILL)`) | Linux: `linux.TestKillKillsEverything`, `TestSignalForwarded`, `TestPIDNamespace`; `e2e` cancel-with-descendants case checks no process and no cgroup remain |
| 6 | Memory, CPU and PID limits are applied before the first user instruction runs: init is cloned directly into a cgroup that already has `memory.max`, `cpu.max`, `pids.max` set. | `internal/runtime/linux/runtime.go` (`Start`: `tree.Create` with limits, then `clone3(CLONE_INTO_CGROUP)`), `internal/cgroup/cgroup_linux.go` | Linux: `cgroup.TestCreateLimitsStatsKillRemove`, `linux.TestMemoryLimitOOM`, `TestPIDsLimit`; `e2e` memory-limit case |
| 7 | A workload cannot see, read or write the host filesystem other than its own workspace. Rootfs is read-only; `pivot_root` detaches the old root; mounts are `nosuid,nodev`; the daemon serves artifacts only through `os.Root`, never following symlinks outward. | `internal/runtime/linux/mount.go`, `internal/executor/executor.go` (`OpenArtifact`, `validArtifactPath`) | Linux: `linux.TestFilesystem`; unit: `executor.TestArtifacts` (`..`, absolute, symlink escape, directory, non-regular); `e2e` artifact cases |
| 8 | A workload runs with an empty capability set, `no_new_privs`, a seccomp filter on every thread, and in fresh PID/mount/UTS/IPC/net (and user) namespaces. The network namespace has only loopback. | `internal/runtime/linux/runtime.go` (`SysProcAttr` flags), `init.go` (`setupSandbox` order: rootfs → hostname → lo → caps → uid → capset → no_new_privs → seccomp), `caps.go`, `seccomp*.go` | Linux: `linux.TestPrivilegesDropped`, `TestSeccompDeniesNamespaces`, `TestNoNetwork`, `TestWithoutUserNS`; unit: `linux.TestSeccompFilterAssembles`, `TestSeccompBlocksInChild` |
| 9 | Nothing untrusted runs before the sandbox is fully set up. The init performs all setup and only then `exec`s the command; if any step fails, init reports the error on the status pipe and exits, and the daemon marks the job `failed` / `start_failed` and removes its cgroup and workspace state. | `internal/runtime/linux/init.go` (`RunInit`), `runtime.go` (`Start` status-pipe handshake, cleanup on error) | Linux: `linux.TestStartFailureCleansUp`, `TestStartCancelled`; unit: `executor.TestOutcomes` ("start error" case) |
| 10 | The workload environment is exactly `PATH`, `HOME` and the request's variables. The daemon's environment never reaches a job. | `internal/executor/executor.go` (`buildEnv`), `internal/runtime/linux/runtime.go` (init started with an empty environment), `init.go` (exec with the config's env) | unit: `executor.TestEnvDoesNotLeakDaemonEnvironment`, `TestDefaultEnv`; Linux: `linux.TestEnvironmentIsExact` |
| 11 | Log retention per job is bounded by `MaxLogBytes`; writers never block on readers; a slow subscriber loses chunks (accounted in `dropped_bytes`), not the job. | `internal/logbuf/logbuf.go` (`Write` eviction, non-blocking fan-out) | unit: `logbuf.TestEviction`, `TestSlowSubscriberDropAccounting`, `TestConcurrentWritersAndSubscribers`; executor `TestLargeOutputIsBoundedAndDoesNotDeadlock` |
| 12 | Client disconnects never affect a job. A log stream closing only drops that subscription; the job's lifetime is owned by the executor. | `internal/api/sse.go` (`streamLogs`: job never tied to `r.Context()`) | unit: `api.TestLogsHistoryAndDisconnect` |
| 13 | Graceful shutdown: new submissions are refused (503), queued jobs finish as `cancelled`/`shutdown` without starting, running jobs get SIGTERM then SIGKILL, and the process exits within `--shutdown-timeout`. | `internal/executor/executor.go` (`Shutdown`), `scheduler.Shutdown`, `task.Discard`, `cmd/sandboxd/serve.go` | unit: `executor.TestShutdown`, `scheduler.TestShutdown*`, `api.TestShuttingDown`; Linux: `e2e` shutdown case |
| 14 | API errors never contain host paths, syscall names or Go error internals. Unknown errors become `INTERNAL` with the detail logged server-side; readiness failures become a fixed message. | `internal/api/api.go` (`fail`), `cmd/sandboxd/serve.go` (`Ready`) | unit: `api.TestInternalErrorsAreGeneric`, `TestNotFound` |
| 15 | Only directories and cgroups named like a canonical UUIDv4 job id are ever deleted during startup cleanup; nothing else under the state dir or cgroup tree is touched. | `internal/job/id.go` (`ValidID`), `executor.CleanupStale`, `cgroup.Tree.RemoveStale` | unit: `executor.TestCleanupStale`, `job.TestIDs`; Linux: `cgroup.TestRemoveStale` |
| 16 | No goroutine or file descriptor outlives its job: output pumps end at EOF or are detached after `drainTimeout`, `Process.Close` runs after `Wait`, subscriptions are closed with the buffer. | `internal/executor/task.go` (`supervise`, `close`), `internal/runtime/linux/process.go` | unit: `executor.TestNoGoroutineLeak`; Linux: `linux.TestStartFailureCleansUp` (cgroup removed), `e2e` cancel case (cgroup directory gone) |

## Known deliberate gaps

- Invariant 5 relies on `cgroup.kill` (Linux ≥ 5.14). On older kernels the
  runtime falls back to killing the PIDs listed in `cgroup.procs`, which can
  race with a fork bomb; `pids.max` bounds the damage.
- Invariant 3 has a 10 s ceiling after SIGKILL. A process stuck in an
  uninterruptible kernel wait is reported finished and its cleanup is handed
  to a background goroutine; `sandboxd_cleanup_failures_total` counts this.
- Invariant 6 does not bound workspace disk usage or kernel memory that the
  cgroup does not attribute to the job.
